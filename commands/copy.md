## What this does

Single entry point for every copy task. Routes to the correct domain sub-command, injects pre-write gates (Channeling / Coat-of-Arms / One-Person), and fires post-write reviewers (One-Person-Enforcement / Proof-Density / Emotional-Sequence / Objection-Coverage / Teardown) as sub-agents.

**Zero system-prompt weight** — this is an explicit command, not an auto-activating skill. Nothing loads unless you type `/copy`.

**Related reference library:** `.claude/references/copywriting-os/` — gates + reviewers + frameworks. Sandbox holds all 47 copywriting.ai newsletter extractions (retrieve via `ctx_search` when a gate needs a specific fact).

## Step 1 — Route

Parse `$1`:
- `sales-letter` → `/copy:sales-letter $2`
- `email` → `/copy:email $2`
- `landing` → `/copy:landing $2`
- `ad` → `/copy:ad $2`
- `headline` → `/copy:headline $2`
- empty or unknown → ask: **"What copy do you need? (sales-letter / email / landing / ad / headline)"** then re-route.

Every sub-command inherits the gate + reviewer chain below. The sub-command owns the domain module (delegates to existing skill). This command owns routing + gates + reviewers.

## Step 2 — Load shared context (ONCE per session, cached on disk)

Required files (surface missing ones before writing):

- `clients/<slug>/context-profile.json` — business identity (required)
- `clients/<slug>/copy-system/copy-brief.md` — compressed ~2K summary. If missing, generate from `context-profile.json` + `_brand/offer.md` + `_brand/buyer-profile.md` + `_brand/avatars/*` + `source-of-truth.md` (if exists). Write to disk.
- `voice/<person>/brand-voice.md` — writer voice
- `clients/<slug>/_brand/avatars/<avatar>.md` — the specific avatar this copy targets (if >1 avatar, confirm with operator which)
- `clients/<slug>/copy-system/coat-of-arms.md` — Halbert portrait for this avatar (auto-generated by the gate below if missing)

**Do NOT** pre-load the 47 newsletters or framework reference library into main context. They live in the context-mode sandbox. A gate or sub-agent queries `ctx_search` only when it needs a specific fact.

## Step 3 — Pre-write gates (run in order; HITL if any fail)

Load and apply, in order:

1. `.claude/references/copywriting-os/gates/channeling-check.md` — Schwartz/Collier: name the EXISTING desire we're channeling + the internal conversation the reader is already having. FAIL → abort, operator decides.
2. `.claude/references/copywriting-os/gates/coat-of-arms-generator.md` — Halbert: load or generate the audience coat of arms. FAIL → operator provides missing specifics.
3. `.claude/references/copywriting-os/gates/one-person-seed.md` — Halbert: inject the "write to one real person + declare at end" instruction into the writer's prompt.

When all 3 pass, hand off to Step 3b.

## Step 3b — Pre-write grounding builders (fire in parallel as sub-agents)

Before the sub-command writes, populate the two grounding files that B1 (claim-verification) and B4 (buyer-language-fidelity) depend on. Spawn 2 sub-agents in parallel:

1. `.claude/references/copywriting-os/builders/proof-inventory-builder.md` — harvests every citable claim from `context-profile.json` + `source-of-truth.md` + `_swipe/research/*` + `_brand/avatars/*` + `testimonials/*` into `clients/<slug>/copy-system/proof-inventory.md`, tagged by the 6 proof types.
2. `.claude/references/copywriting-os/builders/objection-matrix-builder.md` — maps every heard objection to one of 6 categories with grounded handlers, writes `clients/<slug>/copy-system/objection-matrix.md`.

**Re-use rule:** if these files already exist and were built within the last 14 days, skip unless operator requests refresh. Builder run history in `clients/<slug>/copy-system/quality-gates/builder-log.md`.

When both files are fresh, hand off to the sub-command.

## Step 4 — Sub-command writes

Sub-command (`/copy:sales-letter`, `/copy:email`, etc.) delegates to its existing skill:
- `/copy:sales-letter` → `skills/sales-letter-method/` (via existing `/content:sales-letter` command)
- `/copy:email` → `skills/email-sequence/`
- `/copy:landing` → `skills/copywriting/` (landing page mode)
- `/copy:ad` → `skills/ad-concept-engine/` + `skills/big-angle-spotter/`
- `/copy:headline` → `skills/headline-bank/`

The existing skill runs its full pipeline — it already has voice, unslop, and copy-editing wired in. We add our gates + reviewers around it.

**Heavy work runs in a sub-agent.** Main thread receives only the final draft + sub-agent summary.

## Step 5 — Post-write reviewers (fire in parallel as sub-agents)

Spawn 9 sub-agents using the `verification-loops` pattern, in two parallel banks. Each receives the draft + one reviewer spec. Main thread never loads reviewer bodies.

**Phase B — Anti-hallucination (grounding verification):**

1. `.claude/references/copywriting-os/reviewers/claim-verification-audit.md` — every factual claim traces to a grounding-file source line; coverage ≥ 95% + zero CRITICAL unsourced.
2. `.claude/references/copywriting-os/reviewers/forbidden-content-audit.md` — no banned words, saturated angles, voice violations, or AI-tell patterns (F1-F6 categories).
3. `.claude/references/copywriting-os/reviewers/specificity-audit.md` — no weasel words where grounding has concrete numbers; density < 4 per 1000 words.
4. `.claude/references/copywriting-os/reviewers/buyer-language-fidelity-audit.md` — quoted buyer language verbatim-matches research; paraphrases preserve register (no upshift drift).

**Phase C — Quality (persuasion craft):**

5. `.claude/references/copywriting-os/reviewers/one-person-enforcement.md` — verify the writer declared a specific reader at end; reject generic declarations.
6. `.claude/references/copywriting-os/reviewers/proof-density-audit.md` — every major claim has ≥1 of 6 proof types; target ≥80% density + ≥4/6 types present.
7. `.claude/references/copywriting-os/reviewers/emotional-sequence-audit.md` — 6 states covered in order (Indifference → Pain → Understanding → Hope → Belief → Desire); no skips.
8. `.claude/references/copywriting-os/reviewers/objection-coverage-audit.md` — all 6 objection categories addressed or explicitly N/A with reason.
9. `.claude/references/copywriting-os/reviewers/teardown-reviewer.md` — element-by-element failure-mode check (hero / lead / body / proof / CTA).

All 9 fire in parallel (single tool-call batch). Phase B results are strictly gating — any Phase B FAIL blocks ship regardless of Phase C verdicts.

**Existing reviewers also fire** (they're already wired into the domain skills): `brand-voice-guardian` agent, `unslop` Layer 1, `copy-editing` Sweep 8 de-AI.

## Step 6 — Synthesize + revise

Collect all 9 reviewer verdicts. Phase B failures are strictly gating — resolve them first before touching Phase C.

**Phase B failures (grounding — block ship):**

- **Claim-Verification fail** = remove unsourced claims OR source them from grounding files OR demand operator confirmation on HIGH severity numbers.
- **Forbidden-Content fail** = rewrite banned phrases; swap saturated angle if re-used as primary theme; rerun unslop + copy-editing Sweep 8 for AI-tell violations.
- **Specificity fail** = substitute weasel words with concrete numbers from grounding index; leave genuine unspecifiable hedges as LOW-severity annotations.
- **Buyer-Language-Fidelity fail** = rewrite upshifted register back to source register; remove fabricated quotes; verify testimonial names exist.

**Phase C failures (persuasion craft):**

- **One-Person-Enforcement fail** = re-write required (generic imagined reader → generic copy).
- **Proof-Density fail** = injection of proof elements; single revision pass.
- **Emotional-Sequence fail** = structural reorder; sub-command's Phase 2 stitcher re-fires.
- **Objection-Coverage fail** = targeted inserts per flagged category.
- **Teardown fail** = element-level rewrites of hero / lead / body / proof / CTA per flagged failure modes.

Run Phase B revisions first, then Phase C. Re-fire the relevant reviewer(s). Max 2 revision cycles per phase before escalating to operator (HITL).

## Step 7 — Ship + log

**Learnings** append to both:
- `skills/<domain-skill>/learnings.md` (the specific skill that ran)
- `clients/<slug>/learnings.md` (per-client intelligence)

If any critical input missing, surface before writing. Do NOT fabricate.
