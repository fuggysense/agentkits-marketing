## Notes / things noticed (NOT fixed — out of scope)

- **Pre-existing dependency gap:** `gspread` is not installed in this environment or in `.venv`. `source_of_truth_sheet_writer.py` and `patch_angle_cell.py` `import gspread` transitively at MODULE TOP (via `from modal.sheets_writer import SheetsWriter`), so a bare `python3 -c "import ..."` fails on ImportError even though the code is syntactically valid. `ad_concept_sheet_writer.py` does this lazily (only when `not dry_run`). Consider making the import lazy in those two too so dry-run/`--help` work without gspread — left as-is per "surgical / fix only what the task names."
- **Template double-duty:** `clients/_smoketest/_brand/metrics-config.json` is BOTH the live smoketest config AND the canonical onboarding template (placeholder `{{...}}` shape with a top-level `{{GOOGLE_SHEET_ID}}`). Because the flatten guard is `if "sheet_id" not in raw`, a top-level placeholder sheet_id silently disables campaigns[] flattening — meaning an onboarding config that keeps the top-level `sheet_id` placeholder will never read its campaigns[] entries. Real clients (neezanizam) omit the top-level `sheet_id`, so they're fine. Flagged, not fixed. The fixture sidesteps this by living in a sibling file with the real (no-top-level-sheet_id) shape.
- `--metrics-campaign` was added because folder slug (`thomson-reserve`) != metrics-config campaign slug (`thomson-reserve-buyers`) for the live TR data. Defaults to `--campaign` when they match.
- The TR writer's live path uses the `gws` CLI (human OAuth, `jerel@genflos.com`), NOT the SA creds — so `resolve_credentials` is currently informational/parity for that writer (it surfaces the SA identity in the warning). It does not change the live-write auth. Documented here so a future live-write refactor knows the creds path is resolved but unused by `_gws_update`.
