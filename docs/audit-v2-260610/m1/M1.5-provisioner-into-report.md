# M1.5 — sheets-provisioner `--into` destructive bug

**Task:** Patch `provision_from_template.py` so `--into` only appends/creates its own tabs and never deletes or modifies pre-existing tabs. On a name collision, fail loudly with the colliding tab name (no overwrite, no delete).

**Audit ref:** D-13 (AUDIT-REPORT.md:109), E-handoffs.md:100.
**Branch:** rebuild-v2. **No external/network calls, no live sheet writes** (google libs not installed locally — Modal-only — verified by `py_compile` + a stubbed-API harness).

---

## Root cause

`provision_from_template.py` used one variable, `old_tab_ids`, for two semantically opposite purposes:

- **`--title` (new workbook):** `old_tab_ids` = the single auto-created "Sheet1" placeholder, which *should* be deleted after the template tabs land. Correct.
- **`--into` (existing workbook):** `old_tab_ids = [s["properties"]["sheetId"] for s in dmeta["sheets"]]` collected the sheetId of **every pre-existing tab** in the operator's live workbook (line 97). The delete loop (lines 121–122) then queued a `deleteSheet` for each one. Result: pointing `--into` at a populated client workbook wiped all its tabs (live metrics history included) before copying the template in.

The delete and the collect were both unconditional, so `--title`'s legitimate placeholder cleanup and `--into`'s destructive nuke shared the same code path.

## What changed (file:line, post-edit numbers)

`skills/sheets-provisioner/scripts/provision_from_template.py`

1. **L13–17 (docstring step 3):** rewrote to state `--into` is append-only, never deletes/modifies pre-existing tabs, and aborts loudly on a name collision. Added a `--dry-run` note + example (L31–32, L38–39).
2. **L70:** added `--dry-run` argparse flag — "read source+dest, print the plan, make NO changes."
3. **L102–135 (destination block):** split the old single `old_tab_ids` into two:
   - `placeholder_tab_ids` — tabs we are responsible for removing. **`--into` sets this to `[]` (L113)**; `--title` sets it to the created Sheet1 (L135).
   - `existing_tab_names` — names already in the `--into` target (L112), used only for collision detection.
   - **Collision guard (L114–120):** `collisions = [t for t in tabs if t in existing_tab_names]`; if non-empty → `sys.exit("REFUSING to provision: these tabs already exist in the --into target (no overwrite, no delete): {collisions}...")`. Fails before any mutating call.
4. **L137–165 (dry-run early-return):** prints the append-only plan (`tabs_to_add`, `tabs_already_present`, `preexisting_tabs_to_delete`) and `return`s **before** the first mutating API call (`copyTo`). No copy/rename/delete/clear/share fires under `--dry-run`.
5. **L168–177 (delete loop):** renamed `old_tab_ids` → `placeholder_tab_ids`. The delete path is now fed only by the placeholder list, which is empty for `--into`.

Net: +66 / -12 lines, one file. No other file touched (logged a stale doc below, did not fix it).

## Branch trace — can `--into` reach the delete?

Delete path = `for sid in placeholder_tab_ids: requests.append({"deleteSheet": ...})` (L176). Reachable only when `placeholder_tab_ids` is non-empty. All three assignments:

| Line | Branch | `placeholder_tab_ids` |
|------|--------|----------------------|
| L113 | `if args.into:` | `[]` — empty → loop runs 0×, **no delete** |
| L126 | `--title` + `--dry-run` | set, but `return` at L165 happens before the loop → unreachable |
| L135 | `--title` live | created Sheet1 id only (the placeholder we made) |

`--into` / `--title` are a `required` **mutually-exclusive group** (argparse L64–66), so exactly one fires. When `--into` is set, `placeholder_tab_ids = []` → **the delete loop iterates zero times. `--into` can no longer reach a destructive delete.** `--into` takes a value, so an empty/falsy `args.into` is not possible from the CLI.
