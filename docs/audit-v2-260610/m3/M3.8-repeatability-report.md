## PART A — Repeatability failures

**Zero.** No step required editing a skill, script, or template to proceed. Every friction item below was worked around inside `clients/_smoketest2/` only.

### Friction log (logged, not fixed — per M3.8 no-fix rule)

1. **Template YAML block contains mustache tokens** (`{{niche}}`, `{{platform_compliance_note}}`). The research-brief.md template's YAML block must be replaced wholesale for a new niche — the `cp -R` leaves unfilled tokens the gate would choke on if not replaced. No template instruction says to do this replacement; the builder interview section implies it but doesn't make it explicit. _Template defect: fill instructions exist in builder-interview prose but not as a machine-enforced step._

2. **context-profile.json ships with all-empty fields and mustache tokens.** The template has no "fill these before the gate runs" instruction. A new onboarder following the template alone would not know which fields are required by downstream scripts. _Template defect: no required-fields annotation._

3. **buyer-profile.md is a 262-line empty scaffold.** At Stage 0, this is noise: the new onboarder has no useful context yet. The file is correctly used as the output target of avatar-research, but the template ships it as a mandatory-looking prerequisite, not an output target. _Template defect (pre-existing): same issue documented in smoketest1 BASELINE.md._

4. **CLAUDE.md ships as ~90 lines of V4 boilerplate** with no client-specific content except `{{client_slug}}` placeholders. For a no-site DTC client (VitalKit), ~40% of the file's sections (Site & Media Isolation Contract, slug-scoped wrangler/mux commands) are noise at onboarding. The file works once filled but the fill instructions are implicit. _Pre-existing defect._

5. **No `_baseline/` scaffolding in template.** Both _smoketest and _smoketest2 created a `_baseline/` directory (or angles/copy subdirs) that don't exist in the template. These are the record-keeping artifacts for the pipeline run — the template should scaffold them or at least reference them. _Template gap._

6. **`00_inputs/market/awareness-sophistication.md` satisfies the gap_analysis artifact check** even though it's an empty scaffold in the template. The gate passes this artifact as long as the file exists and has >=3 non-blank, non-header lines. The template file has enough header lines to fail the real-content check but the existing content just barely qualifies. _Edge case: gate behavior is correct (it checks real content) but a newly onboarded client could leave this half-empty and still pass._
