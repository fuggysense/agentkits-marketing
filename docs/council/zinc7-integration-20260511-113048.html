Blind spots the council caught

  • Regulatory dialect (Reviewer 1): Supplement VSL moves are FTC/FDA scar tissue, not persuasion innovations. Porting them to SaaS/property imports manipulation-coded patterns into unregulated categories.
  • corrections.md diff (Reviewer 2): If these 7 gaps haven't been logged as corrections on real client work, they haven't earned framework status. n=1.
  • Detector failure (Reviewer 4): The audit didn't flag these on prior letters — that's a reviewer-coverage bug, not a parts-catalog shortage.
  • Conversion data (Reviewer 5): Nobody asked if Zinc7 actually converted. These 7 elements might be correlation, not causation.

The recommendation

Do NOT build 5-7 new framework files. 5 of 7 are renames, 10-State is bloat, and the audit instrument is the real bug. But don't stop at the single-field fix either — that ships nothing testable.

Three-step sequence:

  1. Diff before build. Pull corrections.md for sales-letter-method and sales-letter-audit. Check which of the 7 gaps were ever flagged on real client work. Anything not logged = drop it.
  2. Fix the detector, not the catalog. Add discrete-artifact gates inside existing phases: Phase 2 must output "named adversary"; Phase 3 must output "false-solution discredit block"; Phase 1 must output "category sensitivity tier." These are reviewer gates, not new frameworks.
  3. Teardown 3-5 winners per industry (SG property, B2B SaaS, info, services, ecom) before generalizing. One Zinc7 doesn't justify pipeline changes for 5 industries.

Skip the 100-letter library — maintenance graveyard. Skip Phase 2.5 Mechanism Education — it's already Phase 3.
