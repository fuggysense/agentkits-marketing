What this page is: a plain-language map of how the machine now works — where the three client entry points feed in, what happens at each step, and which decisions a human makes versus which ones code enforces automatically.
Section 2
The three client flows
Every client enters from one of these three doors. All three converge at the same gated chain once they're past their entry step.
Door A — New client
Template onboarding
Client folder scaffolded from the template. Research brief generated per-niche. Research runs until the completeness gate passes — thin research blocks here, not downstream.
Door B — Existing client, new wave
/campaign:status → conductor resume
Status board shows where every client sits. Conductor reads pipeline-state.json and resumes at the right step. No re-briefing, no guessing.
Door C — Live client iterating
Metrics cron → feedback-router
Daily metrics pull feeds the feedback-router: NEW (research refresh), BETTER (angle refinement), or MORE (scale variants). Next batch is 80% proven iterations, 20% fresh angles.
All three doors feed into the same chain below
Avatars — verbatim buyer language
Micro-personas built from real research. Every quote carries a source pointer (transcript line or Reddit URL). Invented quotes cannot enter — the provenance field is required.
Gate — code decides Research completeness floor
Niche-adaptive minimum quote/source count. If the research vault is thin, this step refuses to proceed. Fails loud — does not silently downgrade output quality.
Angles + diversity map
Big-angle-spotter runs in hardened mode (now the default). Scores each angle across five dimensions. Diversity map ensures the batch covers different awareness stages, emotions, and formats — not ten variations of the same idea.
Gate — code decides Angle scored 4 of 5 minimum, code decides
Each angle is scored on grounding, specificity, and differentiation. Below threshold, the run regenerates. The model does not grade its own work — a separate scoring pass does.
Hooks + copy
Headlines and primary copy generated from approved angles. Each hook carries an insight tag pointing back to the research source that inspired it.
Gate — code decides Hook gate — insight tags must resolve
Every hook's insight tag is checked against the research vault. If the tag points at nothing, the hook is cut — not passed along with a warning.
Image prompts — 11-pattern library, 5 formats
Prompts built from Ferres' swipe vault (49 proven statics, verbatim anatomy, replication recipes). 11 patterns (e.g. Testimonial Stack, Before/After, Social Proof Strip) across 5 static formats. Not invented from adjectives.
Gate — code decides Claim gate — every number traces to a source or is cut
The claim ledger checks every number and specific claim in copy and image prompts against the source manifest. No source, no ship. This is the gate that would have caught the invented $214,300 figure from the old machine.
Render
render.py reads the current dct.json shape directly — no hand-feeding prompts one by one. Sidecar provenance file written alongside every image: which prompt, which source, which wave.
Gate — code decides Pre-launch rubric
Checks dimensions, file completeness, and copy-to-creative alignment before any human sees it.
Gate — Jerel decides Creative approval
You review rendered images. Code has already cut unsourced claims, thin research, and broken hooks — so what reaches you has passed the factual checks. This gate is for taste and brand judgment, not fact-checking.
Sheet write — gated writer, dry-run first
Generic gated sheet writer (not hardcoded to one client). Runs dry-run by default and shows a diff before touching the live sheet. Provisioner --into no longer deletes existing tabs.
Meta upload — FORCED PAUSED
Ads upload in paused state. The machine cannot go live unilaterally — the upload script cannot set ads to active.
Gate — Jerel decides Enable in Ads Manager
You flip the switch in Meta Ads Manager. No ad goes live without a deliberate human action on your side.
Metrics → feedback loop → back to Door C
Daily metrics cron pulls per-ad data. Kill thresholds (min S$200 spend, 7 days, 5k impressions) prevent early-kill noise. Comment mining feeds VOC slots for the next batch. Router sends the brief back to Door C with NEW / BETTER / MORE tag.
Code gate — pass/fail set by score or source check. Model does not grade itself.
Human gate — Jerel's judgment required. Cannot be bypassed by the machine.
Production step — runs automatically once upstream gates pass.
Section 3
What the machine locks vs what it proposes
Not everything can be code-enforced. The machine is built to lock what can be locked and surface the rest for a human decision.

Anchors — code enforces these

These do not change run to run. Gates enforce them. No exceptions.
  • Research vault + per-niche completeness floor — minimum quote and source count before any generation runs
  • Verbatim buyer language with source pointers — every quote in a persona traces back to a transcript line or Reddit URL
  • 11 proven ad patterns + 5 static formats — citation-verified from Ferres' swipe vault, not invented on the fly
  • Claims ledger — source-or-cut — every number in copy or an image prompt either has a source file citation or is removed before render
  • Persona quotes locked to research lines — the hook gate checks that insight tags resolve to real source content

Creative surface — model proposes

These vary every run. The machine generates options; humans and gates filter them.
  • Which angle — the model picks from the grounded research; hardened scoring cuts weak picks
  • Hook phrasing — the opening line, the emotional register, the specific words
  • Copy voice — tone, sentence rhythm, word choice within the approved angle
  • Visual interpretation of a pattern — how a Testimonial Stack or Social Proof Strip is rendered for this specific offer

The gates sit between them. Code decides pass/fail from scores and source checks — the model never grades its own homework. A generation step that fails a gate regenerates or stops; it does not pass along a warning note for someone downstream to maybe read.

Honest caveat: gates guarantee grounded and well-formed, not will-convert. A claim that traces to a real source can still be the wrong claim for this audience. Conversion comes from running volume, applying the kill and scale thresholds, and feeding comment objections back into the next batch. The machine makes each wave cheaper to produce and safer to ship — it does not replace the test-and-learn cycle.
Section 4
Before and after — 8 changes that matter
What the machine did in the old version versus what it does now. Same stages, different behavior.
Area Before (v1) After (v2)
Invented numbers in creatives $214,300 loan balance — no research source, no research file — rendered into approved Eugene ad images. Nothing caught it. Claim gate checks every number in copy and image prompts against the source manifest before render. No source means the number is cut, not flagged with a warning.
Research quality No definition of "research complete." Thin-research clients and deep-research clients ran through identical (zero) grounding floors. Quality silently varied 100:1. Per-niche completeness gate blocks generation until the research vault meets a minimum. Fails loud. First-time onboarding and later waves both hit the same floor.
Angle gate Hardened scoring mode existed but was opt-in, undocumented in the skill, and the launch path pointed at a directory that did not exist. Most waves ran ungated. Hardened mode is the default. Scored JSON gate (five dimensions, threshold 4 of 5, fail-closed regen). Code decides; not the operator's memory.
Hooks discarded mid-pipeline The angle run produced gated headlines. Those headlines were thrown away. Headline-bank regenerated new ones downstream with no gate — the one factual check in the copy lane certified work that never shipped. Hooks carry resolvable insight tags. The hook gate checks tags against the research vault. A hook with a broken tag is cut before it reaches copy assembly.
Template stamping defects The factory template failed 3 of its own 7 ICM rules. Every new client onboarding cloned the same structural gaps. Template passes its own validator (91-line CLAUDE.md, validator v2 checks content not just structure). Client #2 onboarded with zero out-of-template edits — repeatability proven.
Render and sheet automation render.py and the sheet writer could not read the current dct.json shape. Every wave meant hand-feeding prompts one by one and writing sheet rows manually, which silently dropped the preview and snapshot safety steps. render.py repointed to the current dct.json shape. One generic gated sheet writer (not hardcoded to one client). Dry-run default shows diff before touching the live sheet.
Where is every client? Held in the operator's head or scattered across ad-hoc notes. No cross-client view existed. State index files lagged folder truth across all three crawled clients. /campaign:status board reads every client's campaign registry and state files and prints one line per client: where the work sits and what comes next. Index auto-sync (dry-run default).
Proof Improvement claims were hypothetical — no second client had been run through the rebuilt template. Second client (different niche, different compliance requirements) onboarded through the new template with zero hand-edits outside L3. Repeatability is a measured result, not a design goal.
