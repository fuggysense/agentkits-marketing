# CLAUDE.md Architect

Unified skill for creating, updating, auditing, and scoring CLAUDE.md files across the marketing agent kit. Combines surgical update logic, quality scoring, and marketing-aware context routing.

**This skill can write to CLAUDE.md files.** After presenting a quality report or proposed changes and getting user approval, it updates files with targeted improvements.

## Modes

| Argument | Mode | When |
|----------|------|------|
| _(empty)_ | **Auto-detect** | Reads root, decides create/update/fix |
| `create` | **Create** | New project — interview + codebase scan |
| `audit` / `score` | **Audit** | Quality scoring with 100-point rubric |
| `[what changed]` | **Update** | Surgical edits with prune logic |
| `[folder path]` | **Nested** | Subdirectory CLAUDE.md |

## Workflow

### Phase 1: Discovery

Find all CLAUDE.md files:
- `./CLAUDE.md` (project root)
- `./clients/*/CLAUDE.md` (client-specific)
- `./.claude/rules/*.md` (project rules)
- `~/.claude/CLAUDE.md` (global — include in audit mode)
- `.claude.local.md` (personal/local)

### Phase 2: Mode Dispatch

**No file** → Create mode. See [references/templates.md](references/templates.md).

**File exists but bad** (missing Vision, no WHY, over 400 lines, generic knowledge) → Remake mode.

**File exists and good** → Update mode. See [references/update-guidelines.md](references/update-guidelines.md).

**Audit argument** → Score all files. See [references/quality-criteria.md](references/quality-criteria.md).

### Phase 3: Execute

For **Create**: Run interview (9 questions, 3 rounds), scan codebase, generate from template. NEVER auto-generate without interview.

For **Update**: Apply surgical edits with prune logic:
1. **Generalize**: Third similar rule → delete specifics, write ONE principle
2. **Deduplicate**: Overlap → merge into one stronger entry
3. **Expire**: No longer true → delete
4. **Promote/demote**: 3x regression → Critical Rule. Irrelevant rule → deleted

For **Audit**: Score each file against rubric, output quality report, offer to fix issues found.

### Phase 4: Validate

After any write/edit:
1. **Line count**: Over 300 → extract to `.claude/rules/`
2. **One-line test**: Every line — "Would removing this cause a mistake?" If no, delete.
3. **Score check** (audit mode): Report grade, flag red flags

## Memory Hierarchy

Know where content belongs — don't put it in the wrong file:

| Priority | File | Scope |
|----------|------|-------|
| 1 | `~/.claude/CLAUDE.md` | Global (all projects) |
| 2 | `~/.claude/rules/*.md` | Global rules |
| 3 | `./CLAUDE.md` | Project (team, via git) |
| 4 | `./.claude/rules/*.md` | Project rules |
| 5 | `./clients/<project>/CLAUDE.md` | Client-specific |
| 6 | `.claude.local.md` | Personal (gitignored) |
| 7 | `skills/*/learnings.md` | Skill-specific learning |
| 8 | `clients/*/learnings.md` | Client-specific learning |

**Routing rule**: If a learning is about a specific skill → `learnings.md`. If about a client → client's `learnings.md`. If about how YOU work → `USER.md`/`SOUL.md`. Only project-wide rules and gotchas go in CLAUDE.md.

## Key Benchmarks

- **Vercel (2025)**: Good CLAUDE.md = 100% task success vs 53% without. 56% skill miss rate without routing.
- **ETH Zurich (Feb 2026)**: Auto-generated files REDUCE success 0.5-3%, increase cost 20%+. Each unnecessary instruction adds 14-22% reasoning tokens.
- **HumanLayer (2025)**: ~150-200 instruction capacity. Bloated files = content ignored uniformly.

**Sweet spot**: 150-200 lines, past ~300 quality degrades.
