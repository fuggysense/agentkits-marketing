# Metrics Wire — campaign → Modal cron → Google Sheet

One guided run per new campaign. Chains existing tools — `sheets-provisioner`, `scripts/modal/setup/provision_campaign.py`, the deployed Modal app — and proves the pipe with a live verified write before declaring done. Built from `scripts/modal/ONE_CLICK_ONBOARDING_PLAN.md` (Phase 1).

**Inputs to collect (the only judgment calls):** client slug · campaign slug + label · ad account (`act_…`) · Meta campaign ID(s) to filter (or account-level totals) · which tabs/frequency.

## Phase 0 — INVENTORY (mandatory, never skip — never create what exists)

Check, in order, and report a one-screen status table before touching anything:

1. `clients/<slug>/_brand/metrics-config.json` exists? Campaign already registered in it? → if fully wired, STOP: report "already wired" + sheet URL + last snapshot date from `clients/<slug>/metrics/`.
2. Registered sheet reachable? `skills/sheets-provisioner/scripts/find_or_create_sheet.sh --client <slug> --campaign <slug> --dry-run`.
3. Service account known? Read `provisioning.service_account` from config (or note absent).
4. Meta side: `meta auth status` → `meta ads adaccount get <act_id>` (system user can see the account — fail fast: "grant access in Business Manager") → `meta ads campaign get <id>` for each given campaign ID (exists + belongs to that account).
5. Modal app deployed + secrets present? `modal app list` shows marketing-metrics; secrets `meta-ads` + `google-sheets` exist.

## Phase 1 — PROVISION (only the missing pieces)

- **Sheet:** the runtime SA has NO Drive quota — it cannot create sheets. Create via `gws` human OAuth path in `sheets-provisioner` (find_or_create), or if blocked, give Jerel the exact one-click instruction: create blank sheet, share `<service_account>` as Editor.
- **Tabs + config:** `python3 scripts/modal/setup/provision_campaign.py --client-slug … --campaign-slug … --label … --ad-account-id … [--meta-campaign-id …] --sheet-id <existing>` — idempotent, writes `metrics-config.json` entry.
- **Service account:** default = client's existing SA from config. New client wanting a unique SA: scripted `gcloud iam service-accounts create` in the client's GCP project + key into Modal secret — flag this as the slow step and confirm with Jerel before creating GCP resources. Shared-SA fallback is acceptable for a 48h validation test.

## Phase 2 — DEPLOY

Client configs are baked into the Modal image at build time — **redeploy is unavoidable** after any config change:
```bash
cd scripts/modal && modal deploy marketing_metrics.py
```

## Phase 3 — VERIFY (live test, the point of this skill)

1. Dry run: `modal run marketing_metrics.py::run_for_client --client-slug <s> --campaign-slug <c> --dry-run` — Meta rows populate, no write.
2. Live test write: same command without `--dry-run` for yesterday's window.
3. **Confirm landing:** read the target tab back (gspread/`gws sheets +read`) and verify the new row is in the RIGHT tab of the RIGHT sheet — compare sheet ID against config, not against memory.
4. Report: status table → what was created vs reused → sheet URL → any manual step still owed (Business Manager grant, sheet share).

## Failure modes to catch (from the plan — fail loudly)

- Wrong/typo'd ad account or campaign ID → caught in Phase 0 step 4, before anything is created.
- Sheet not shared with SA → Phase 0 step 2 read fails; output the SA email + share instruction.
- Config written but no redeploy → Phase 2 is non-optional; verify `modal app list` timestamp moved.
- Test write lands in wrong tab → Phase 3 step 3 compares actual vs config.

## Division of labor (don't blur)

- `metrics-wire` (this) — one-time wiring + proof, per campaign.
- Modal cron (`scripts/modal/marketing_metrics.py`) — routine daily/weekly/monthly writes. THE implementation.
- `sheets-updater` — manual lane only: ad-hoc pulls, HITL preview, debugging.
- `sheets-provisioner` — sheet find-or-create + auth model (`references/sheet-auth.md`).
