# Critical Rules

## What this file teaches

These are the nine hard rules every sales letter must obey. They are not style preferences. Each one is a line the drafter or reviewer cannot cross. Most of them come from real tests that won, or from the failure modes we have already paid for.

## The rules

1. **Context first, framework second.** Skip components that do not fit the offer. Never force all 12 components into a letter that does not need them.

2. **Specific beats clever.** Use real numbers, real names, real timeframes. "$526K every 4 years" beats "great returns." Anything vague reads as filler.

3. **Real proof or real credentials.** If the operator has no client results yet, pivot the Proof Stack to credentials, methodology, or sample work. Never make up testimonials. Never invent a result.

4. **Light scarcity or none at all.** Real capacity limits only — "5 spots this month" or "30 bookings to keep quality high." Heavy countdowns read as pressure tricks for high-ticket consulting. Cut them.

5. **The guarantee carries the conversion.** With no price on the page, the guarantee is the main reason a stranger says yes. It is not optional.

6. **FAQ and P.S. are not negotiable.** Eight out of eight modern competitor pages we scraped skipped these. That gap is your moat. Always include both.

7. **The de-AI pass runs before delivery.** Every time. No exceptions. AI-shaped language kills trust faster than any other single problem.

8. **No price anchoring.** This skill is for lead-gen funnels with no price on the page. Pricing-page work belongs in the `copywriting` skill.

9. **Chat-only output by default.** Never write the final letter or any draft to disk without the user saying yes. The full draft delivers in chat. The user reviews. The user says `y`, `save`, or `ship it`. Only then write to `clients/<slug>/sales-letters/<YYMMDD>-v1.md`. If the user says `edit`, loop back to the Phase 2 stitcher. If the user says `n`, discard. See `/content:sales-letter` for the full approval gate.

## Assertions a reviewer can score

1. Letter uses only the components that fit the offer. No forced components. *(yes / no)*
2. Every promise has a number, a name, or a timeframe attached. *(yes / no)*
3. Every proof element is real — sourced from a real client, real credential, or real sample. *(yes / no)*
4. Scarcity, if present, names a real capacity limit. No countdown timers, no fake "only X left." *(yes / no)*
5. The letter has a guarantee block. *(yes / no)*
6. The letter has both an FAQ block and at least one P.S. *(yes / no)*
7. The letter passed the de-AI pass (Sweep 8 from the `copy-editing` skill). *(yes / no)*
8. The letter does not name a price. *(yes / no)*
9. The letter was approved by the user before it was written to disk. *(yes / no)*
