# Common Failure Modes

## What this file teaches

These are the nine ways sales letters fail most often. Each one has a name so reviewers can flag it cleanly. If you see the pattern, name it, then fix it.

## The patterns

- **The "force all 12 components" trap.** The drafter packs every component into the letter even when only 8 fit the offer. The letter feels bloated. Cut the components that do not earn their space.

- **The vague-promise trap.** The letter promises a benefit with no number behind it. "More leads" instead of "12 booked calls a month." Vague promises read as filler. Add the number or cut the line.

- **The generic-headline trap.** The headline could be used by any of ten other businesses in the same space. The headline must name something only this offer can say. If a competitor could paste it onto their page and it still works, it is too generic.

- **The "we're great" Proof Stack.** The proof is about the operator, not the buyer. Real proof shows results from buyers who look like the reader. If the proof reads as "look how good we are" instead of "look at people like you who won," rewrite it.

- **The "Submit" CTA.** The button says Submit, Send, or Click Here. The button must say what the buyer gets. "Book my free strategy call." "Send me the playbook." Outcome language, not action language.

- **The heavy-urgency trap.** Countdown timers, "only 24 hours left," red exclamation marks. For high-ticket consulting, this reads as pressure tactics. Use real capacity limits instead.

- **The "skip the FAQ because it looks long" trap.** Five objections, two sentences each. That is ten sentences. It is not long. Skipping the FAQ throws away one of the highest-converting blocks. Always include it.

- **The "lost numbers after de-AI" trap.** The de-AI pass strips AI-shaped patterns, and the drafter forgets to put the specific numbers back in. Re-inject the numbers after every de-AI sweep.

- **The "skipped Phase 0.7" trap.** The drafters write without the Phase 0.7 mechanism + offer architecture document. They improvise the mechanism name. They dismiss competitors at category level ("most agents fail to follow up") instead of naming alternatives. The letter ships with a forgettable mechanism and a weak discredit of the old way. Phase 0.7 is a hard input. Drafters running without it is a hard error.

## Assertions a reviewer can score

1. Letter uses only the components that fit. No forced components. *(yes / no)*
2. Every promise has a specific number or timeframe behind it. *(yes / no)*
3. Headline names something only this offer can claim — a competitor could not reuse it. *(yes / no)*
4. Proof points to buyers who look like the reader, not to the operator's own greatness. *(yes / no)*
5. CTA button uses outcome language, not "Submit" or "Send." *(yes / no)*
6. Urgency, if present, names a real capacity limit. No countdowns. *(yes / no)*
7. FAQ block is present. *(yes / no)*
8. Specific numbers survived the de-AI pass. *(yes / no)*
9. Phase 0.7 mechanism + offer architecture document was a required input for Phase 1. *(yes / no)*
