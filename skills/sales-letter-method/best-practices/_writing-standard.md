# Writing Standard — the two questions

Every output this skill produces — from a best-practices file, to a retrofitted reference, to a reviewer's notes, to the final letter copy that ships — must pass these two questions before it ships.

## Question 1 — Is this a complete argument?

Read the file from top to bottom the way a real reader would, in one pass, cold.

- Does the reader understand the whole thing by the time they reach the end?
- Is anything missing that the reader needs to follow the logic?
- Are there elements that don't belong here — that distract, confuse, or throw them off?
- Does the file earn each claim it makes, or does it leap?

Mark every section. If a section loses the reader, fix it or cut it. If a section is foreign — research log notes, internal-only framing, codes nobody outside the team would recognise — cut it.

## Question 2 — How simple is the language?

The reader is a smart Singaporean using third-grade English. Native English speaker. Not a marketer, not a copywriter, not a researcher.

Cut every one of these on sight:

- **Jargon** — "load-bearing element", "quarantine the ask", "control-beating element", "function attestation"
- **Codes** — F1, A1, A2, A3, V2. Use names: "the price-and-order P.S.", "the deadline-restate check"
- **Industry words** — "controls" (use "real tests that won"), "the ask" (use "the request to buy" or "the pitch"), "pattern attestation" (use "we noticed this in the notes")
- **Long compound sentences** — anything over 20 words, split it
- **Passive voice** — "the move was abandoned" → "writers stopped using the move"
- **Anything that makes the reader feel "not okay"** — talked down to, excluded, confused, having to look words up

## Order

Q1 first (does it hang together as an argument), Q2 second (is the language simple enough). Structural fix first, language fix second. Both must pass before the file ships.

## How to check

Before shipping a file: re-read it cold, top to bottom. If you stumble on a sentence, your reader will too. Rewrite that sentence.

## A note for reviewer agents reading BP files

The BP files are scaffolding, not a cage. Apply the named patterns and checks from the BP file you are reading, BUT also bring your general copywriting judgment — especially for issues the BP file does not cover.

Example: cohesion-check.md teaches you about transition bridges between sections. It does NOT teach you about section ordering. If a letter's "Why us" section sits awkwardly between mechanism and CTA, that is a real cohesion problem the BP file doesn't name — flag it anyway. Don't go silent on issues just because the BP file doesn't have a check for them.

Use BP rules as evidence anchors. Use general judgment as breadth coverage. Both.
