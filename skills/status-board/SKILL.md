# Status Board

Answers one question fast: where does every client's work sit right now, and who's holding it up.

Run this when the operator asks "where is every client", "what's next", "who's blocked", or wants a cross-client status read at the start of a session. It is not a per-campaign deep dive. For one campaign's full dashboard, use `/campaign:status <client> <campaign>`.

## Run it

```bash
python3 scripts/status_board.py                 # every client
python3 scripts/status_board.py eugene-chieng    # one or more named clients
python3 scripts/status_board.py --json            # machine-readable, for piping
```

Output is plain text, capped under 40 lines. One line per active campaign:

```
<client>: <campaign/workspace> @ <phase> — next: <action> — blocked on: <operator|client|gate|nothing>
```

A `[stale: index <date> < artifact <date>]` tag means work happened on disk after the campaign index was last bumped. That is the signal to go update the index (or to distrust the phase the index claims).

## What it reads

The script never guesses paths. Per client it walks, in this order:

1. `clients/<client>/campaigns/_campaigns-index.json` — the campaign registry.
2. Whatever each registry entry points at: `campaign-index.json`, `state.yaml`, or a DCT `dct-tracker.json`.
3. The active workspace's `pipeline-state.json` for the deepest current phase and any blockers.
4. Folder mtimes, when none of the above name a phase.

Clients with no registry get a folder-truth fallback line that says "unindexed" and names the newest campaign folder. Clients with no campaigns at all show as idle. Archived campaigns and template stubs are dropped.

DCT clients (neezanizam) collapse to the newest DCT per funnel, so a client running two funnels shows two lines, not twelve. The `(+N more)` suffix counts what was collapsed.

## How to read the output

- **blocked on: gate** — waiting on an approval gate (AG1/AG2, eval, sign-off). The work is done; someone has to say yes.
- **blocked on: operator** — waiting on you (a review, a taste pass, a decision the script can see is pending).
- **blocked on: client** — waiting on the client to deliver something (testimonials, confirmations, account access).
- **blocked on: nothing** — the next action is yours to just do.

The blocker is classified from the phase and next-action text, so it is a heuristic, not gospel. When a line surprises you, open the file it came from before acting on it.

## Hard rules

- Read-only. The script touches nothing, makes no network/Meta/sheet/render calls.
- It surfaces verbatim strings from data files (next-action text, blocker notes). Treat those as the file's claim, not verified fact.
- If two clients disagree with what you remember, the disk wins. Re-read the named file.
