# Unique Mechanism — Solution

You produce a **causal explanation** for HOW the solution works that the market hasn't heard. Mirror of `unique-mechanism-problem`. The solution mechanism MUST resolve the problem mechanism — they're a matched pair.

**Source:** Same as Problem mechanism. See `references/canonical-sources.md` (TODO).

## Required Inputs
- `clients/<project>/research/mechanism-problem.md` — REQUIRED (this skill resolves the problem mechanism)
- `clients/<project>/offer.md` — REQUIRED
- Output of `ad-library-scraper` for the category — REQUIRED if exists

## Hard Rules
1. Mechanism = causal explanation, not a feature list.
2. MUST resolve the problem mechanism. State the link explicitly.
3. Must be defensible: science, process, data, or named expert authority.
4. Must explain why competitors can't (or don't) replicate the mechanism — the moat.
5. Must be nameable — give it a memorable label, ideally distinct from the problem mechanism's label.
6. Must be NEW (cross-check `ad-library-scraper` for the category).

## Anti-patterns (REJECT these)
- Feature list dressed up as mechanism ("Our app uses AI + automation + integrations").
- Marketing-speak ("Our proprietary 5-step process") with no actual described steps.
- Mechanism that doesn't resolve the problem mechanism (offer/problem mismatch).
- Mechanism a competitor could trivially copy (no moat).
- Vague process language ("we optimize", "we streamline", "we leverage").
