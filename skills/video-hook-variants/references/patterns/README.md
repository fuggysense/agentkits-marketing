# Patterns — Operator-Curated Learnings

This folder captures hook patterns discovered through live campaigns, A/B test results, and post-launch analysis. It grows over time as real data replaces assumptions.

## What goes here

- Proven hook formulas with verified performance data (CTR, hook rate, scroll-stop %)
- Failure patterns — hooks that tested well on paper but underperformed in market
- Client-specific hook patterns (e.g., "Takekine Gen-Z visual hooks outperform verbal-led hooks by 2:1")
- Platform-specific notes (TikTok vs. Meta feed vs. Reels — scroll-stop thresholds differ)
- Emergent patterns from the example bank (e.g., "stakes + specific number > stakes alone")

## How to add a pattern

Create a new `.md` file in this folder. Name it descriptively:
```
<date>-<pattern-slug>.md
```
Example: `260521-gen-z-visual-stakes-outperforms.md`

Each file should include:
- **What the pattern is** (1–2 sentences)
- **Evidence** (campaign, concept ID, platform, metric)
- **When to apply it** (trigger conditions)
- **When NOT to apply it** (boundary conditions)

## Why this folder exists

Frameworks in `references/frameworks/` are methodology — they don't change based on one campaign. This folder captures what actually happened in market. Over time it becomes the most valuable folder in the skill — a compounding empirical record that separates this hook methodology from generic frameworks.

Do not add speculative patterns. Every entry must have real-world evidence behind it.
